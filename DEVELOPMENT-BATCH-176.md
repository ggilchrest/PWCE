# Development Batch 176 — Immutable producer admission evidence

Status: `verified` for the producer contract and HTTP proof component. Complete canonical Lifestream admission/invocation mapping remains in progress.

The trusted admission response now includes `admissionEvidence`, derived solely from its stored action. The separately published `pwce-action-admission.v1@1.0.0` schema and profile define the original action fingerprint, identity and scope, input, capability, grant revision, target, approval terms, deadline, admission time/decision, original snapshot and admission precondition. Current action status, attempt and result remain separate. The proof is unchanged when duplicate admission reads a completed or uncertain action.

The public contract closes previously unspecified nested admission fields without rewriting the existing core, dispatch or capability bundle. Its explicit dependency pins and ordered path/byte digest must be adopted by the consumer. The fingerprint is canonical JSON text, not a digest. Snapshot and precondition records preserve their original JSON strings and SHA-256, including nested property order, so canonicalizing the outer response does not corrupt custody. The producer checks the actual stored fingerprint, snapshot scope and known capability, original timestamps, approval terms and precondition integrity before emitting proof.

Static authenticated bundle/schema reads create no authority, approval or action. Actual proof remains on the trusted admission response, protected by the existing separate dispatcher credential. It is not a signature, bearer permission, target-call claim or effect confirmation. A response error after admission can leave the original admission stored; it never establishes rollback or authorizes a replacement command.
