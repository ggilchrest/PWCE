Check light availability before dispatch

What changed

PWCE now checks the selected Home Assistant light before admitting a new action and again before sending its command. Unavailable or mismatched state prevents dispatch. Repeating an existing request returns its original result.

Why it matters

A light can become unavailable after you approve it. Approval alone no longer lets that action proceed.

What to test

  • Inspect local context QA — use the safe automated check for unavailable targets, changed access, expiry and retries.

Where to read more

Why an approved light action can still be denied.

Screenshots updated

None. Studio controls and layout are unchanged; the existing captures still show those controls.

Known issues / follow-ups

A device can change after a read, and a sent command still needs independent confirmation. Complete Lifestream action integration and physical-device acceptance remain open. Validation used simulated Home Assistant responses, without changing saved services or live settings.
