Local Studio authentication

Direct callers now authenticate to the local Studio API with a development bearer token, while the browser uses a local session.

What changed

  • Set PWCE_STUDIO_TOKEN for scripts and direct API clients.
  • The Studio browser creates an HttpOnly same-origin session on loopback.
  • Unauthenticated API requests fail closed before they reach runtime or action services.

Why it matters

The local control surface now has an explicit authentication boundary without putting the Home Assistant token in the browser bundle or persisted PWCE state.

What to test

  • QA: Inspect local context and request a safe action — confirm the browser session loads the Studio and direct API calls use the configured token.

Where to read more

  • Inspect local context and request a safe action — updated setup requirements.

Screenshots updated

  • No visual screenshot change; the browser session is verified through the local API boundary.

Known issues / follow-ups

  • Studio transport authentication and GatewayService authority-context issuance are not yet unified.
