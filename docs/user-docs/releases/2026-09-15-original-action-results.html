Keep original action results visible

What changed

Integrations can now verify an action result against its original permission and dispatch attempt. Later confirmation keeps the first reply visible. A failed reply whose physical effect is unknown can still be checked without sending the command again.

Why it matters

You can see what was originally reported and what was later confirmed, without mistaking partial success or an uncertain reply for full success.

What to test

  • Inspect local context and request a safe action — run the original result proof checks, including legacy records, later confirmation and corruption rejection.

Where to read more

  • Check the original action result.

Screenshots updated

None; Studio controls and layout are unchanged.

Known issues / follow-ups

Lifestream invocation and status mapping remains in progress. Older targets with no declared stable identity have an explicit proof-unavailable result. These checks do not establish physical-device or Human acceptance.
