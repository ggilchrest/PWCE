Separate action permission from execution

A trusted integration can check and record permission before it sends the exact approved action.

What changed

A separate host connection requires both the Assistant's scoped credential and a distinct dispatcher credential. Its first call records permission without sending a command. Its second call must match that original action. Repeated calls cannot send it twice; an uncertain reply remains uncertain.

Why it matters

An integration can preserve the difference between approval, permission and execution while keeping PWCE in charge of the action.

What to test

  • Inspect local context and request a safe action — run the new synthetic admission and HTTP checks, including missing credentials, changed access and duplicate commands.

Where to read more

Known issues / follow-ups

The complete configured Lifestream action workflow remains in progress. These checks use synthetic targets and do not establish physical effects or Human acceptance. No saved deployment was reconfigured or restarted.
