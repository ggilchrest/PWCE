Action interruption recovery

What changed

An interrupted action now stays uncertain until its outcome is checked. Restarting or repeating a request cannot silently send it again. Expired approvals, changed access, invalid brightness values and a different requested capability version stop a new action.

An external Assistant can read an action only under its original identity and execution scope. Approvals created before this stricter binding need fresh review. An unfinished older admission without a deadline cannot dispatch.

Why it matters

You can distinguish a completed action from one whose outcome is still unknown, without risking an accidental repeat.

What to test

  • Inspect local context QA — focus on the action recovery criteria and synthetic regression command.
