Inspect local context and request a safe action

Use this local development journey to see what PWCE knows, inspect its evidence, and prepare a reversible light action without claiming that it succeeded too early.

Before you start

  • For a Human-protected Studio, set PWCE_STUDIO_USERNAME, PWCE_STUDIO_PASSWORD, and PWCE_STUDIO_RECOVERY_CODES. Keep recovery codes offline.
  • Start the development server with npm run dev.
  • Open http://127.0.0.1:4173/.
  • Configure local Home Assistant or use seeded development data.

Walkthrough

  1. Open PWCE Studio.

    If Human access is configured, sign in with the local username and password. Use one offline recovery code only when recovering access.

  2. Choose a site from “Home site”.

    The current evidence, explanation, history, Agent question, and action request use the selected site.

  3. Review “Runtime”, “Current state”, and “Current evidence”.

    The page shows explicit health, knowledge, source, time, and observation references.

  4. Preview, request approval, approve locally, and dispatch the light action.

    Each boundary is visible and a disabled or unreconciled effect is not reported as success.

  5. Select “Sign out”.

    The browser session is revoked and the sign-in form returns.

Tips & troubleshooting

  • Keep recovery codes offline and replace the development account if all codes are consumed.
  • Runtime offline means Home Assistant is unavailable; check the local container and token reference.
  • Unknown, stale, or conflicted context is honest evidence status, not a missing UI value.
