Inspect local context and request a safe action

Part of: Inspect local context and request a safe action

Purpose

Verify that Studio Human sign-in protects the local inspection and controlled-action journey while preserving honest evidence and approval behavior.

Preconditions

  • For Human-protected Studio, set PWCE_STUDIO_USERNAME, PWCE_STUDIO_PASSWORD, and comma-separated PWCE_STUDIO_RECOVERY_CODES. Keep recovery codes offline; each works once.
  • Run the local Home Assistant development container or seed the PWCE development state.
  • Start PWCE Studio with npm run dev.
  • Use a browser at http://127.0.0.1:4173/.

Acceptance Criteria

Testing Instructions

  1. Open http://127.0.0.1:4173/.

    When Human access is configured, you should see “Sign in to PWCE Studio”.

  2. Enter an incorrect username or password and select Sign in.

    Sign-in fails without opening the Studio.

  3. Sign in with the configured local credentials.

    You should see the Studio overview and authorized site data.

  4. Select Sign out, then sign in with one recovery code.

    Studio opens. Sign out and try the same recovery code again; it must fail.

  5. Complete the existing context, preview, approval, and dispatch checks.

    No action is reported successful before reconciliation.

Edge cases

  • Missing or partial auth configuration → startup fails closed.
  • Used recovery code → authentication_failed.
  • No Home Assistant configuration → home_assistant_not_configured.
  • Expired, stale, conflicted, or unknown evidence remains explicitly labeled.
