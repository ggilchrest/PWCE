QA: Inspect local context and request a safe action

Part of: Inspect local context and request a safe action

Purpose

Verify that a developer can authenticate to Studio, choose an authorized Home Assistant site, inspect its runtime health and evidence, preview a reversible action, complete its local approval step, and dispatch it while seeing an honest persisted outcome.

Preconditions

  • For Human-protected Studio, set PWCE_STUDIO_USERNAME, PWCE_STUDIO_PASSWORD, and comma-separated PWCE_STUDIO_RECOVERY_CODES. Generate codes with npm run studio:generate-recovery-codes; keep them offline and use each once.
  • Run the local Home Assistant development container or seed the PWCE development state.
  • For multi-site coverage, start the optional Home Assistant profile and configure both site tokens.
  • Start PWCE Studio with npm run dev.
  • Use a browser at http://127.0.0.1:4173/.

Acceptance Criteria

Testing Instructions

  1. Run npm run studio:generate-recovery-codes and save the output offline.

    The command prints fresh codes and does not write credentials or state.

  2. Open http://127.0.0.1:4173/.

    You should see “Sign in to PWCE Studio” when Human access is configured; otherwise you should see “PWCE Studio” and “Local development”.

  3. Enter an incorrect credential and select Sign in, then sign in with the configured local credentials.

    The invalid attempt fails; valid credentials open the Studio and authorized site data.

  4. Review “Runtime”, “Current state”, and “Current evidence”, then select Explain current state.

    The page shows explicit health, knowledge, source, time, observation, and freshness information.

  5. Ask the Agent a current or history question.

    The answer uses the selected site and includes evidence references when available.

  6. Choose a brightness and select Preview request.

    The action result shows an outcome and rationale codes. No external effect occurs during preview.

  7. If approval is required, select Request approval, then Approve locally.

    The Studio shows the approval result without dispatching an effect.

  8. Select Dispatch approved action.

    The Studio shows the persisted Action status. A disabled live route is denied; an unverified service acknowledgement remains outcome_unknown.

  9. Select Sign out, then sign in with one recovery code. Sign out and try that recovery code again.

    The session is revoked; the first recovery sign-in succeeds and reuse fails.

Edge cases

  • Missing or partial auth configuration → startup fails closed.
  • Invalid credentials → authentication_failed.
  • Used recovery code → authentication_failed.
  • No Home Assistant configuration → the page stays usable and reports home_assistant_not_configured.
  • No accepted observation → current state is “Unknown”, not an invented value.
  • Expired freshness window → current state is “Stale”, not presented as current.
  • Same-time disagreement → current state is “Conflicted”, not collapsed to one value.
  • Home Assistant WebSocket interruption → runtime status becomes degraded or offline while bounded reconnect attempts are scheduled.
  • Live effects disabled → preview denies the live route.
  • Expired or mismatched approval → dispatch is denied.
  • Service acknowledgement without matching state → result stays outcome unknown.
