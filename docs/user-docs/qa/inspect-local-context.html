Inspect local context and request a safe action

Part of: Inspect local context and request a safe action

Purpose

Verify local Studio Human sign-in, one-time recovery, sign out, and the evidence-first controlled-action journey.

Preconditions

  • For Human-protected Studio, set PWCE_STUDIO_USERNAME, PWCE_STUDIO_PASSWORD, and comma-separated PWCE_STUDIO_RECOVERY_CODES. Generate codes with npm run studio:generate-recovery-codes; keep them offline and use each once.
  • Run the local Home Assistant development container or seed the PWCE development state.
  • Start PWCE Studio with npm run dev.
  • Use a browser at http://127.0.0.1:4173/.

Acceptance Criteria

Testing Instructions

  1. Run npm run studio:generate-recovery-codes and save the output offline.

    The command prints fresh codes and does not write credentials or state.

  2. Open Studio and try invalid credentials.

    Sign-in fails without opening the Studio.

  3. Sign in with local credentials, then select Sign out.

    Studio opens, then the session is revoked and the sign-in form returns.

  4. Sign in with one recovery code, sign out, and try that code again.

    The first sign-in succeeds; the second fails.

  5. Complete the context, preview, approval, and dispatch checks.

    No action is reported successful before reconciliation.

Edge cases

  • Missing or partial auth configuration → startup fails closed.
  • Used recovery code → authentication_failed.
  • No Home Assistant configuration → home_assistant_not_configured.
  • Expired, stale, conflicted, or unknown evidence remains explicitly labeled.
